## 5. Product vision and hard invariants

ContextDesk is a Linux/KDE Plasma 6/Wayland cockpit for one Logitech G213
Prodigy. Preserve the product vision and these invariants:

- G213 only, USB `046d:c336`; no other keyboards, no generic remapper, no
  Windows/macOS. Target CachyOS/Arch, Plasma 6, KWin, Wayland, systemd,
  C++20/Qt6/KF6.
- Exactly **five RGB zones, not per-key RGB**. Never design or show per-key
  color control as a real capability. Zone names in order: Left Area, Middle
  Area, Right Area, Arrow and Homekeys, Numpad.
- Foreground context is event-driven via the KWin scripting API — no
  `xdotool`/`wmctrl`/`xprop`, no title polling. Prefer KWin
  `desktopFileName`/`resourceClass`/`resourceName` identity over `/proc` or
  window captions.
- The session app **never opens raw keyboard event nodes**; only the input
  broker does, and it starts disabled. No automatic ARM after restart, resume,
  crash, or reconnect.
- One persistent OpenRGB SDK connection on loopback (protocol 5), never a CLI
  process per focus change; one RGB backend at a time.
- Typed action model only: no arbitrary shell strings. Fail-safe default is
  pass-through; unset means inherit, not swallow.
- G213 controls in scope: F1–F12, Previous, Play/Pause, Next, Mute, Volume
  Down, Volume Up, Game Mode, Backlight. Game Mode and Backlight are
  firmware-only (no host event); never silently substitute PrintScreen or Pause.
- Never log ordinary typed keystrokes, raw event lines, key names, scan values,
  typed content, serials, host addresses, host keys, passwords, private paths,
  desktop IDs/names, or window captions in code logs, prompts, reports, or META.
- Suspend goes through logind/systemd policy, never `/sys/power/state`.
  Display-off must not alter KScreen topology.
- input-remapper is not inspected or reconfigured.
- Licensing is unresolved: root `LICENSE` is MIT, but handout §25 says the
  COOPERATOR has not selected the license. Never copy external code (G213Tray
  is GPL-3.0-or-later) before an explicit compatible decision. Gate G6.

### 6.1 Verified technical surface (re-verify; do not trust blindly)

Read-only reconnaissance from the predecessor session and earlier verified
analysis:

- `org.kde.KWin` `/VirtualDesktopManager`, interface
  `org.kde.KWin.VirtualDesktopManager`, exposes read/write properties and
  methods: `createDesktop(uint position, QString name)`,
  `removeDesktop(QString id)`, `setDesktopName(QString id, QString name)`,
  read/write `rows` and `navigationWrappingAround`; properties `count` (u),
  `current` (s, a desktop **UUID**, not an index), `desktops` (`a(iss)`:
  position, id, name); signals `currentChanged`, `countChanged`,
  `desktopCreated`, `desktopRemoved`, `desktopDataChanged`.
- KWin Scripting API exposes `window.desktops = [desktop]` and
  `window.maximized` for compositor-enforced placement/maximization.
- KDE Plasma native Window Rules (`kwinrulesrc`) provide persistent,
  compositor-enforced placement without polling. The reference host currently
  has an almost-empty `kwinrulesrc`.
- Application launching candidates: systemd user transient scopes
  (`systemd-run --user`, systemd 261 verified present) or XDG/desktop-file
  launchers. `KF6Service` and `KF6WindowSystem` CMake configs are present;
  `KF6KIO`/`KF6Runner`/`KF6Parts`/`KF6Package` are present. `gio` and `kstart`
  are present; `kioclient6` is absent. No `extra-cmake-modules` and no KF6
  umbrella config — per-component `find_package(KF6<Pkg> REQUIRED)` only, and
  `KF6::Config` is really `KF6::ConfigCore`/`KF6::ConfigGui`.
- The existing KWin bridge (`kwin/contextdeck-bridge/contents/code/main.js`)
  already tracks `workspace.windowList()`, `windowActivated`, `windowAdded`,
  `windowRemoved`, resolves identity through `transientFor`, and sends
  `ContextReport`/`InventoryReport`/`Heartbeat`. It never sends captions.

### 6.2 High-risk design boundaries the Planner must resolve before any code

These are not settled. They require explicit, durable decisions:

- **Host mutation class.** Creating/removing virtual desktops and writing
  `kwinrulesrc` mutate the COOPERATOR's live desktop configuration. They are
  irreversible-ish, need a recovery/revert path, and are COOPERATOR-owned.
  M4 planning must separate read-only observation from mutation, and any
  mutation slice needs its own bounded authority and checkpoint.
- **Title fallback vs privacy rule.** Invariant §5 forbids caption-based
  identity by default and forbids title polling. A title fallback must be
  event-driven and must define exactly what (if anything) is compared, stored,
  or logged, and must be opt-in. Treat captions as sensitive; do not log them.
- **Launching is a new side-effect class.** Launches must be typed (desktop
  file / KService id), never shell; must not become autostart; must be
  reversible; and must define failure/duplicate handling.
- **Assignment vs existing matcher.** M4 assignment of apps to desktops should
  reuse the existing typed profile/matcher model rather than inventing a second
  semantic owner. Decide whether desktop assignment is a new schema field
  (schema 4?) or derived; migration must preserve schema 1–3 behavior.
- **Autostart boundary.** Do not let M4 drift into G8/M5. Autostart remains
  blocked until M2/M4/G6/G8 prerequisites pass.
- **UI/UX polish.** The COOPERATOR reports the current UI as confusing. M4 is a
  natural place to include an explicit, bounded UI/UX review slice, but UI
  polish must not silently change accepted M1/M3 semantics.
