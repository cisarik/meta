## 6. Why this candidate is selected

Current AP already contains an explicit compact-communication model.

It permits stable AP safety and protocol material to remain in durable owners rather than being mechanically recopied into every Worker prompt.

Current AP also requires task prompts to remain self-contained for the actual task-specific boundary, including repository identity, authority, allowed paths, prohibitions, Git authority, validation, stopping conditions, session routing, and activated risk surfaces.

`PROMPT_CONTRACTS.md` explicitly states that it is not a collection of fixed giant prompts and that inactive annexes are omitted rather than copied with invented values.

Despite that architecture, recent real AP orchestration has repeatedly produced very large Worker prompts containing extensive copies of stable Git, security, lifecycle, reporting, and role guidance.

This creates a concrete architecture question:

```text
Is current AP sufficiently actionable about what a prompt must state locally
versus what it should inherit by reference from stable AP owners?
```

The objective is not raw brevity.

The objective is:

```text

with minimum duplicated stable protocol material
```

A useful shorthand is:

```text

```

## 8. Concrete candidate failure classes

Worker 1 should test at least these classes against real evidence.

### Stable-rule duplication

A prompt recopies durable AP rules that are already owned elsewhere.

Potential consequences include context consumption, harder human review, duplicated maintenance, contradiction risk, and reduced visibility of the actual task-specific authority delta.

### Authority loss through over-compression

A compact prompt omits repository identity, immutable baseline, path allowlist, side-effect authority, Git authority, stop conditions, validation, Worker-session routing, or another required task-specific field.

That is unsafe compression.

### Inactive-annex leakage

A prompt includes provider, browser, deployment, production, privilege, recovery, INFOSEC, acceptance, publication, or another generic annex even though the task does not activate it.

### Historical-context duplication

A prompt replays predecessor narratives and rejected alternatives instead of carrying the smallest accepted decision or immutable evidence anchor needed by the new Worker.

### Generic negative-scope explosion

A prompt copies long lists of universal prohibitions even though only a smaller task-specific subset materially distinguishes the current grant.

The investigation must determine where repetition is still necessary to prevent ambiguity.

### Report-contract excess or ambiguity

A prompt restates large generic reporting prose instead of activating the compact report core and only the task-specific evidence surface.

### False compactness

A prompt appears concise only because it relies on conversation memory, Meta history, hidden system context, a particular client's implicit instruction loading, or Worker inference.

That is not valid self-contained task authority.

Each material failure must be classified as:

```text
observed
reproducible
structurally inevitable
plausible but unobserved
cosmetic
disproved
```
