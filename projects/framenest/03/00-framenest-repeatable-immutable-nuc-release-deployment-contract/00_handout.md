## 11. FrameNest product intent that must survive restoration

FrameNest is a local-first, private/shared searchable media memory and fast reaction picker.

Its core loop is:

```text
acquire or upload
→ preserve original
→ bounded explicit analysis
→ human-reviewable metadata/tags
→ search/filter in seconds
→ explicit Save/publish
→ reuse as a reaction
```

The real-world X objective is:

> While signed into X and viewing or replying to a post, the user can save useful meme media into FrameNest and can quickly find an existing FrameNest meme and attach it to the open X reply without navigating through the full FrameNest application.

The result must feel simple enough for ordinary users, not like an operator console.

Primary content scope:

```text
static meme images
animated images/GIF-like media
short meme videos
```

Explicitly excluded from the X picker:

```text
YouTube videos
movies
ordinary long-form videos
unpublished/private media belonging to another requester
```

YouTube and movies remain in FrameNest but are not searchable or attachable through the X meme surface in this MVP.

## 13. Extension-first architecture hypothesis

The preferred first architecture is a Brave/Chromium extension, not a native cross-platform desktop application.

Important network simplification:

> A browser extension does not need to bundle a Tailscale module merely because FrameNest is reached through Tailscale. When Tailscale is installed and connected on the operating system, Brave uses the host network stack and can reach the tailnet FrameNest origin subject to normal origin, HTTPS, CORS, cookie, identity, and extension-permission rules.

Therefore the initial hypothesis is:

```text
Brave/Chromium Manifest extension
+ existing OS Tailscale connection
+ existing FrameNest server
+ narrow x.com and FrameNest-origin permissions
```

The planning Worker must verify this against current Brave/Chromium extension APIs and the actual FrameNest/Tailscale Serve origin.

A lightweight native tray application or Native Messaging host remains **parked** unless evidence proves the extension alone cannot perform the required clipboard/file-upload/attachment interaction safely and reliably.

Do not bundle a VPN/tunnel client into the first MVP.

```text

```

- an administrator's explicit Save action may request the already-supported analysis/tagging pipeline as part of that explicit action;
- analysis must remain reviewable and must not silently overwrite canonical administrator metadata;

- multi-media X posts, unsupported media, size/duration limits, provenance, attribution, cleanup, and failure feedback must be decided from current backend behavior.

### 14.2 Find a FrameNest meme while composing an X reply

With focus in an X reply composer, a keyboard shortcut or extension action opens a lightweight meme picker.

The picker must:

- search only media eligible for the X meme surface;

- show a compact visual result grid;
- exclude YouTube and movies by server-enforced query/filter semantics, not only visual hiding;
- respect requester/private/published visibility and role authorization;
- make the selected meme attachable with the fewest practical steps.

### 14.3 Attach, do not auto-post

Selecting a meme should place or attach it into the currently open X reply composer through the safest supported browser mechanism.

The extension must **not** automatically submit the reply/post. The user reviews and presses X's Post/Reply control.
