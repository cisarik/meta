Category

General

Offer all four. youtube is a semantic category under ADR-0055, not an acquisition-source proxy; excluding it would force unnecessary administrator correction for valid YouTube-related content saved from X. The helper text is:

Category describes the content and applies to every media item in this post. Movie genres can be added later in FrameNest.

Movie is valid with zero genres at ingest. No genre picker or checkbox forest is added.

The new UI always supplies a category. The API field remains optional for old clients:

photo tile default: general;
video tile default, including X animated-GIF-as-video: meme;
unknown synthetic media host default: general;
mixed post: the clicked tile supplies the initial default, but the helper explicitly says the final choice applies to every asset;
backend inspection never silently changes the visible user selection.
Keyboard and focus
Opening the popup moves focus into the iframe and then to Title.
Focus order from Title is Description → checked category radio → Tags → selected-tag removal buttons → capability-gated Analyze → Save. Shift+Tab from Title reaches header Close.
Native radio behavior owns Arrow keys and Space; Enter on a radio is suppressed and never submits.
Enter in Tags accepts the highlighted suggestion; with no suggestion it does nothing.
Plain Enter in Title does not submit. Description retains newline behavior.
Enter/Space on Save submits; Ctrl+Enter or Cmd+Enter submits from elsewhere.
Escape first closes an open tag list; otherwise it closes the popup.
Close, Escape, outside click, and completed submission restore focus to the initiating +.
While submitting, mark the form aria-busy, disable mutable fields and Save actions, but keep header Close usable. Use polite status for progress and alert semantics for validation failure.
No mouse-only category interaction is introduced.
Media promise
Native X video remains MP4-backed.
X animated_gif remains user-visible as GIF while normally storing the provider’s MP4 representation; do not promise literal GIF bytes.
A literal GIF representation is accepted only when explicitly identified and confirmed by the existing GIF validator.
Ordinary X photos are supported when the provider-native representation is JPEG or PNG.
WebP and other still formats are rejected without transcoding.
Maximum four native assets per post; one selected category applies to all.
Unsupported/private/deleted/live/external-link, oversized, overlong, malformed, or changed media fail with sanitized codes.
Duplicate, conflict, and correction rules
Same requester, successful post, explicit category matching every live cataloged asset: reuse the claim and apply alias changes; report Already saved to FrameNest.
Same requester, successful post, different or internally mixed canonical category: reject with HTTP 409 X_REQUEST_CATEGORY_CONFLICT; do not mutate category or alias.
Same requester, active claim, same persisted category: active reuse.
Same requester, active claim with another category, or a legacy NULL category: reject 409 rather than race or overwrite intent.
Omitted category from an old client asserts no category and retains existing reuse behavior.
A create race must compare the transactionally selected active winner before returning active_reuse.
Another requester receives an independent private claim and logical media under the current keep-separate policy.
Retry preserves the original claim category, including NULL legacy semantics. Successful assets are not re-downloaded.
Administrator correction changes only canonical media rows through the existing capability-gated metadata API. It does not rewrite claim intent, acquisition source, or creator provenance.
If an administrator corrects only part of a multi-asset claim, later explicit duplicate Save detects the mixed categories and fails honestly.
Every + belonging to the same permalink mirrors the same pending and terminal state.
Terminal presentation
Active states: busy spinner, “Saving to FrameNest…”.
completed: green check, “Saved to FrameNest”.
create disposition reuse or state duplicate_resolved: green check, “Already saved to FrameNest”.
completed_partial: amber warning, “Partially saved to FrameNest (S of N)”.
failed: danger-border plus, “Save to FrameNest failed”; optionally append a fixed friendly explanation mapped from the sanitized code.
catalog_removed: danger-border plus, “Saved item is no longer available in FrameNest”.
POST network ambiguity: amber “Save status unknown—check FrameNest”; never claim definite failure or success.
Poll transport failure: retain inflight recovery, retry with bounded exponential backoff for two minutes, then leave an unknown warning and recheck on later page recovery.
Unknown server state: fail closed as status unknown and retain recovery.
A single hidden aria-live="polite" region announces post-level status changes.

On every download or retry:

For photos, the bridge re-resolves and downloads within one bounded subprocess, so the candidate URL is never persisted or placed in a command line.

Photo transport and validation
Accept only:

HTTPS;
exact host pbs.twimg.com;
no user information, fragment, non-443 port, backslash, or non-/media/ path;
only name=orig and an optional agreeing format=jpg|jpeg|png query;
no redirects.
Resolve DNS in the bounded subprocess, reject every non-global address, connect to a selected vetted address while retaining TLS SNI/certificate verification and Host: pbs.twimg.com, and therefore avoid DNS rebinding. Send Accept-Encoding: identity.

Require status 200, expected Content-Type, positive optional Content-Length, JPEG/PNG magic agreement, 30-second connect/read limits, and a 64 MiB photo ceiling. Stream into claim-owned 0600 staging, hash while writing, fsync, and atomically promote only a complete file. Never log URLs, query strings, response bodies, or bytes.

Use a neutral fixed X staging artifact artifact.bin; video/photo temporary names are internal and normalized before handoff. Extend the shared descriptor-safe staging implementation with a configurable fixed artifact name whose YouTube default remains artifact.mp4. Display filename extension is derived from validated expected MIME, not XMediaType.

The existing upload quarantine validator remains authoritative for complete decoding and accepts only:

JPEG and PNG still images;
maximum dimension 8,192;
maximum 33,177,600 decoded pixels;
existing GIF/MP4 rules.
Map downstream validation rejection back to a stable X asset failure instead of generic catalog failure.

Multi-asset failure behavior
Asset-scoped terminal failures mark only that asset failed and continue acquiring other assets. Claim-wide failures still fail the claim immediately.

Some cataloged, some failed → completed_partial.
One asset and it fails → preserve its specific code.
Multiple assets and none succeed → X_MULTI_ASSET_FAILED, with individual sanitized asset codes retained.
Retry eligibility uses is_retryable_x_failure(asset.failure_code); terminal format, host, source-change, and policy failures are not retryable.
Response reducer
Create one explicit outcome reducer shared conceptually by initial response and polling. The service worker:

recognizes terminal states including catalog_removed;
never infers terminality from a failure code;
persists only nonterminal claims;
forwards post ID, disposition, counts, retryability, and sanitized code;
retains inflight records on ambiguous transport failure.
The content script associates controls by post ID, not one button object, allowing recovery and permalink-wide status mirroring.
