## 6. Deep analysis — four dimensions were mixed in one radio

This section is **Orchestrator recommendation / analysis**. It is not an
accepted decision and not mutation authority.

FrameNest already stores three orthogonal columns plus tags. Save UI collapsed
them.

| Dimension | Repository truth today | User-facing job | 03/06 Save UI mistake |
|---|---|---|---|
| `MediaKind` | `image` \| `video` \| `animated_image` (not user-editable) | What the file **is** | Hidden; radios pretended to be this |
| `AcquisitionSource` | `x_manual_claim`, `youtube_manual_claim`, `manual_upload`, `library_scan`, `unknown` (immutable after create, ADR-0055) | **Where it came from** | Relabeled `general` as **X** |
| `ContentCategory` | `general` \| `meme` \| `movie` \| `youtube` (ADR-0045, ADR-0055) | Gallery facet: Memes / Movies / YouTube | Offered YouTube as a Save radio; then parked it and used X instead |
| Canonical tags | Ordered keys, website can create, companion cannot | Semantic labels (“meme”, topics) | Underused; user now wants Meme **here** |

**Michal is right that X and YouTube are sources.** The catalog already has
`acquisition_source`. Website Edit media already shows it **read-only**. Save
on X must not ask “is this X?”. It **is** X. A future YouTube **+** must not
ask “is this YouTube?”.

**He is also pointing at a real overload in ContentCategory.** `meme` is
cultural, `movie` is long-form-with-genres, `youtube` was added so Gallery
YouTube would **not** be a source proxy (ADR-0055 explicitly forbids that
substitution), `general` is the leftover bucket. Putting **X** on `general`
made the overload visible and user-hostile.

### Straight-forward Save (what “+ then Save” actually is)

For an authenticated user on X:

1. Click green **+**.
2. Overlay looks like a **subset of website Edit media**: Title, a **tall**
   Description, tag search (existing keys only), one **Save**.
3. Title prefilled from media **alt** (honest fallbacks below).
4. Description = full tweet text (not the truncated “Show more” snippet).
5. Tags empty unless the user adds canonical ones.
6. **No source control. No category radios.** Source is implied by the
   surface. Category is automatic under **current** server rules until a
   successor ADR says otherwise.
7. Later enrichment (AI title/description/tags, category correction, movie
   genres, Identify movie) happens on the **website / side panel**, which
   already has that workspace. Do not rebuild AI on Surface A.

That Save is **simple**. It does **not** require a new enum.

### The enormous cut (only if Michal insists after seeing the traps)

Replace `ContentCategory` with still / short-video / movie, move Meme to a
canonical tag, and make Gallery YouTube a **source** filter again. That
touches:

- ADR-0045, ADR-0055, ADR-0064, PRODUCT, SPEC, ROADMAP, Gallery chips,
  website category `<select>`, movie-genres gating, sidecar projection,
  Alembic CHECK constraints, backfill policy for existing rows.
- **Picker:** `GET /api/x/companion/media` lists **`meme`** items
  (ADR-0061). Meme-as-tag without a picker rewrite **breaks Attach**.
- **Duration:** “GIF/mp4 = short, Movie = long” needs an explicit threshold
  or stays manual. `MediaKind` already distinguishes image vs video vs
  animated_image; **duration is not a category enum today**.
- AI must still not silently persist category (ADR-0055).

Do not hide that cut inside Save CSS. It is a **planning** whole with a
successor ADR and Michal’s explicit accept of each trap.

### Trap C — Gallery YouTube is a **category** filter (ADR-0055)

Reverting Gallery YouTube to `acquisition_source` **undoes** an accepted
owner decision that existed because source-as-YouTube was wrong for items
that are “about YouTube” vs “from YouTube”. Record this if W2 proceeds.

### Trap D — Picker audience is `content_category = meme`

Attach-from-FrameNest is a **meme picker**, not a full catalog. Meme-as-tag
without a replacement audience (e.g. `MediaKind` + source, or tag `meme`)
is a product break.

### Trap E — `youtube` as ContentCategory vs future YouTube **+**

Future YouTube **+** should set `acquisition_source = youtube_manual_claim`
automatically (already how YouTube acquisition works) and must not ask the
user “YouTube or Meme?”. Whether new YouTube rows still land on
`content_category = youtube` is an ADR-0055 question, not a Save-radio
question.

### Trap F — Brave iframe autofocus

`ui/save.html` in a `chrome-extension://` iframe on `x.com` cannot steal
focus. Keyboard “open → ArrowRight → Enter” without a click **inside** the
overlay will keep failing if we keep the iframe WAR (ADR-0062). W1 should
**stop calling `.focus()` on open** so Errors is quiet, keep **+ then
